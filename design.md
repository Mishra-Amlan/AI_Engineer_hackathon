# design.md — The Unreliable Assistant → Enterprise Grade (v0.1, LOCKED for slices 0–3)

Status: Gate 1 artifact. Changes require an ADR entry (§7). Spec source: Blueprint v2; extensions in CLAUDE.md §9–§13.

## 1. System Charter & Hard Boundaries

**Purpose:** a grounded, tenant-isolated, MCP-enabled enterprise assistant that answers policy/SOP questions with citations and performs *validated* workflow actions.

**In scope:** grounded Q&A (hybrid RAG), SKU/LOT/batch lookups and transitions, triage/routing, model routing with fallback, observability, governance.

**Non-goals / hard boundaries**
- No autonomous clinical, financial or legal execution. Every `TIER_3_MUTATE` action requires HITL approval.
- No ungrounded answers: low retrieval confidence → deterministic abstention.
- No raw PII persisted, cached, logged or sent to a model. No cross-tenant data access, ever.
- No unbounded loops: `max_iterations=5`, circuit breaker on repeated identical failing calls.

**Personas:** End user (asks questions), Operator (approves HITL, reads dashboards), Admin/Tenant admin (policies, budgets, flags), Developer (workbench, evals).

**Scale definitions (OPEN — owner must confirm; see ADR-009):** "millions of users" = registered users; working assumption for capacity model: 1M DAU, 5% peak concurrency = 50K concurrent, ~8.5K sustained RPS, 10x headroom target 85K RPS by slice 13.

## 2. MCP Tool & Data Contracts

Transport: JSON-RPC 2.0. Pydantic v2 strict models (`extra="forbid"`). All requests carry `tenant_id`, `user_id`, `request_id` (UUIDv4), `traceparent`, `deadline_ms`.

| Tool | Server | Tier | Input (key fields, regex) | Output | Errors |
|---|---|---|---|---|---|
| `hybrid_retrieve` | hybrid-rag | T1_READ | `query:str(1..2000)`, `top_k:int(1..50)=4` | `chunks[{id,text,score,source}]`, `confidence:float` | `E_RAG_TIMEOUT`, `E_INDEX_UNAVAILABLE` |
| `lookup_sku` | state-store | T1_READ | `sku: ^SKU-\d{3}$` | `{sku,status,qty}` | `E_NOT_FOUND`, `E_SCHEMA` |
| `lookup_lot` | state-store | T1_READ | `lot: ^LOT-\d{5}$` | `{lot,status,flags}` | `E_NOT_FOUND`, `E_SCHEMA` |
| `compute_summary` | state-store | T2_COMPUTE | `ids:list[str]` | `{summary}` | `E_SCHEMA` |
| `transition_workflow` | state-store | T3_MUTATE | `entity_id`, `to_state`, `idempotency_key: UUIDv4` | `{status:"PENDING_APPROVAL"\|"APPLIED"}` | `E_HITL_REQUIRED`, `E_IDEMPOTENT_REPLAY` |
| `graph_subgraph` | graphify-vault | T1_READ | `anchor:str`, `depth:int(1..2)` | `{nodes,edges,tokens}` | `E_NO_ANCHOR` |

**Auto-repair rules (deterministic, pre-validation):** `^SKU-?(\d{1,3})$`→`SKU-%03d`; `^lot\s*(\d{1,5})$`(i)→`LOT-%05d`. Repair is logged (span attr `repair.applied`); unrepairable → structured error, never a retry of the identical call.

**Error envelope:** `{code, message, retryable:bool, remediation:str}`. Error codes are stable API.

**Model contract:** all LLM calls go through `ModelRouter.complete(request: RouterRequest) -> RouterResponse` (tier, messages, schema?, deadline, tenant) — no component calls a provider directly.

## 3. Distributed Topology & Data Flow

```
Client → LB(NGINX/Envoy) → FastAPI workers (stateless, async)
   → Pre-hooks: PII redactor → Injection shield           (fail-closed)
   → Cache lookup (Redis, tenant-namespaced)              → HIT: return
   → Triage Agent (SLM, T=0) → {DIRECT_ANSWER|HYBRID_RAG|TRANSACTION_EXEC|REJECT_OOS}
   → Subagents: Retrieval | Execution | Verification
        ├ MCP hybrid-rag (BM25 → dense → RRF → rerank [ONNX])
        ├ MCP graphify-vault (Obsidian/Graphify, depth ≤2)
        └ MCP state-store (Postgres+pgvector, Redis)
   → Bounded ReAct loop → Circuit breaker → Tier-3 HITL gate (PENDING_APPROVAL in Postgres)
   → ModelRouter (T0..T3, fallback ladder) → OpenRouter / local SLM
   → Post-hooks: RAGAS audit, OTel export → Response
```
Diagram artifact: `docs/workflow_orchestration.png` (Gate 2, generated by `scripts/make_diagram.py`).
Bulkheads: `rag_pool=64`, `db_pool=128`, `llm_pool=256`, plus per-provider pools.

## 4. End-to-End Latency Budget

**Definition (resolves doc ambiguity, ADR-002):** SLA latency = *time-to-first-byte of a streamed grounded answer* for T0/T1/T2 paths; full-completion latency is tracked separately (KPI-25 TTFT ≤180 ms is a sub-budget).

| Hop | p95 budget (ms) |
|---|---|
| Edge + auth | 10 |
| Pre-hooks (PII+injection) | 15 |
| Cache lookup | 5 |
| Triage | 25 |
| BM25 / Dense (parallel) | 25 (max of 12, 25) |
| RRF | 3 |
| Rerank | 45 |
| MCP serialization (total) | 4 |
| Router decision | 5 |
| LLM first token | 180 (T2 stream) |
| Post-hook (async, off path) | 0 |
| **Sum on RAG path** | **≈ 317 → headroom 133 ms to the 450 p95 ceiling** |

Cache-hit path ≈ 35 ms; abstention path < 90 ms. Loop: `per_step=120`, `total=450`; most requests are single-step (KPI-17 ≤ 2.2).

## 6. Failure Mode & Effects Analysis (12 rows)

| # | Component failure | Detection | Deterministic fallback | KPI/Test |
|---|---|---|---|---|
| 1 | Redis down | client error/timeout | bypass cache, per-process LRU, shed load if needed | chaos |
| 2 | Reranker timeout (>45 ms ×) | span timeout | use RRF top-4, mark `degraded`, raise abstention bar | KPI-09 |
| 3 | MCP server crash/hang (>150 ms) | JSON-RPC timeout | trip bulkhead, read-replica index, restart | chaos |
| 4 | LLM 429/5xx | HTTP status | router ladder: retry once → fallback model → lower tier → extractive → abstain | X-05 |
| 5 | Provider outage | breaker open | route to other provider/local SLM | X-05 |
| 6 | Malformed model output | schema fail after repair | one re-ask at same tier, then fallback | KPI-14/15 |
| 7 | Vector/BM25 index unavailable | `E_INDEX_UNAVAILABLE` | alias flip to previous index version | rollback test |
| 8 | Postgres primary down | conn error | read-only mode, queue mutations, no Tier-3 apply | chaos |
| 9 | Cross-tenant cache key collision | key audit/probe | purge namespace, block cache, alert | KPI-28 |
| 10 | HITL approver unavailable | `PENDING_APPROVAL` age | keep frozen, escalate, never auto-approve | KPI-19 |
| 11 | Flag service down | fetch error | last-known-good flags cached locally (fail-safe = guardrails ON) | rollback test |
| 12 | Budget exhausted / runaway loop | budget counter / breaker | downgrade tier → abstain; breaker `HALTED_BREAKER` | KPI-16 |

## 7. Architecture Decision Records

- **ADR-001 Hybrid weights:** RRF k=60, no learned weights; BM25 k1=1.25,b=0.75; rerank threshold 0.42 (tunable via flag; raised to 0.55 in incident mode).
- **ADR-002 Latency definition:** TTFB of streamed answer (see §4).
- **ADR-003 Vector index:** FAISS **HNSW** (efSearch=64); IVF-PQ only if memory-bound (doc conflict resolved).
- **ADR-004 ONNX FP16 reranker + dynamic micro-batching** (batch 32, max_wait 8 ms).
- **ADR-005 Redis key isolation:** namespace `t:{sha256(tenant_id)[:16]}:`; exact-match key `…:q:{sha256(user_id:norm_query)}`; semantic lookup restricted to the tenant namespace; `user_id` excluded from the semantic namespace to meet KPI-27 (doc conflict resolved), included for exact-match entries holding user-specific data. TTL 300 s ± 45 s jitter.
- **ADR-006 Bounded ReAct:** 5 iterations, 120 ms/step, 450 ms total, deterministic state machine.
- **ADR-007 Model Router:** deterministic, config-driven, tiers T0–T3, fallback ladder ending in abstention (CLAUDE.md §9). Dev models are low-cost OpenRouter models set in `.env`.
- **ADR-008 Rollback:** every behavior is versioned and flag-gated; canary + auto-rollback (CLAUDE.md §10).
- **ADR-009 Scale target:** OPEN — owner to define registered/DAU/peak concurrency; capacity model in `docs/capacity.md` (slice 13).
- **ADR-010 Triage latency 25 ms; p99 ≤ 590 ms; token reduction gate ≥45%** (doc conflicts resolved).
- **ADR-011 Audit log:** hash-chain over *post-redaction* payload only.
- **ADR-013 Agreement rescue:** if the reranker is below 0.42 but BM25 top ≥7.0, dense top ≥0.60 and the same chunk is in both lists' top-3, return RRF top-4 flagged `low_confidence` (generation must be strict-extractive, Verification mandatory). Thresholds calibrated on a 34-question set — re-calibrate when the corpus/models change. Disabled in incident mode.
- **ADR-012 Build order:** build → test → gate → next slice (CLAUDE.md §13). Python 3.14 in this environment; production target 3.11+ — code must stay 3.11-compatible.
